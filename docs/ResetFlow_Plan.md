# ResetFlow 프로그램 기획서

## 1. 프로그램 개요

**ResetFlow**는 Windows 포맷 또는 초기화 직후 사용자가 반복적으로 설정하는 개인 Windows 환경, 개발 환경, 프로그램 설치, 폴더 구조를 자동으로 복구하기 위한 Windows 자동화 프로그램이다.

사용자는 USB, 외장 드라이브, 클라우드 저장소 등을 통해 `ResetFlow.exe`를 새 Windows 환경으로 옮긴 뒤 실행한다. 프로그램은 GUI 창을 제공하며, 사용자는 원하는 설정 항목을 개별적으로 On/Off 할 수 있다.

모든 기능은 기본적으로 **Off** 상태이다. 사용자가 명시적으로 On 한 항목만 실행된다.

---

## 2. 개발 목적

Windows 포맷 이후 반복되는 초기 세팅 작업을 줄이는 것이 목적이다.

주요 목표는 다음과 같다.

* Windows 기본 설정 자동화
* 개발 도구 설치 자동화
* 자주 사용하는 프로그램 설치 자동화
* 개인 폴더 구조 생성
* 일부 프로그램 설정 복원
* 실행 실패 시 원인 확인 가능한 로그 제공
* 가능한 기능에 한해 실행 전 상태로 롤백

ResetFlow는 단순 설치 스크립트가 아니라, **포맷 후 개인 작업 환경을 다시 구축하는 복구 도구**이다.

## 3. 핵심 컨셉

### 3.1 기본값 Off

모든 기능은 기본적으로 Off 상태이다.

사용자가 On 한 기능만 실행된다.

### 3.2 전체 On / 전체 Off

사용자는 다음 기능을 사용할 수 있다.

* 전체 On
* 전체 Off
* 카테고리별 전체 On
* 카테고리별 전체 Off

### 3.3 Start 기반 실행

사용자가 원하는 항목을 선택한 뒤 Start 버튼을 누르면 선택된 기능만 실행된다.

### 3.4 실행 전 백업

설정을 변경하기 전에 가능한 범위에서 현재 상태를 백업한다.

백업 대상 예시:

* 레지스트리 값
* 설정 파일
* 환경 변수
* 기존 폴더 존재 여부
* 기존 바로가기 존재 여부
* 설치 여부
* 실행 전 로그

### 3.5 실패 시 롤백

실행 도중 오류가 발생하면 가능한 범위에서 실행 전 상태로 복구한다.

기본 정책은 다음과 같다.

* 설정 변경 기능: 롤백 시도
* 파일 생성 기능: 생성 전 상태로 복구 시도
* 프로그램 설치 기능: 기본적으로 롤백 불완전
* 드라이버 설치 기능: 자동 롤백 대상에서 제외
* 계정 로그인 기능: 자동화 대상에서 제외

### 3.6 로그 제공

오류가 발생하면 사용자에게 다음 정보를 제공한다.

* 실패한 기능명
* 실패 단계
* 사용자용 오류 요약
* 디버그 로그 위치
* 롤백 성공 여부
* 재부팅 필요 여부

## 4. 자동화 범위 분류

ResetFlow의 기능은 자동화 가능 수준에 따라 분류한다.

| 분류       | 설명                   | 예시                         |
| -------- | -------------------- | -------------------------- |
| 자동화 가능   | 프로그램이 직접 처리 가능       | 폴더 생성, 레지스트리 변경, winget 설치 |
| 반자동      | 프로그램이 실행 또는 안내 가능    | 드라이버 설치 도구 실행, 설정 화면 열기    |
| 수동 확인 필요 | 사용자가 직접 확인해야 함       | Chrome 계정 로그인, 일부 앱 내부 설정  |
| 자동화 제외   | 보안상 또는 안정성상 자동화하지 않음 | 계정 비밀번호 입력, 금융/보안 프로그램 조작  |

## 5. 주요 사용자 시나리오

### 5.1 기본 실행 흐름

1. 사용자가 포맷된 Windows에서 `ResetFlow.exe`를 실행한다.
2. GUI 창이 열린다.
3. 모든 기능은 Off 상태로 표시된다.
4. 사용자가 원하는 기능을 On 한다.
5. Start 버튼을 누른다.
6. 프로그램이 관리자 권한 필요 여부를 확인한다.
7. 선택된 기능 목록을 생성한다.
8. 실행 전 백업을 수행한다.
9. 기능을 순서대로 실행한다.
10. 각 기능의 성공 여부를 검증한다.
11. 완료 화면에서 결과를 보여준다.
12. 실패한 기능이 있으면 로그와 롤백 결과를 보여준다.

### 7.2 대상 계정

* `jihoonkim0508@gmail.com`
* `msc24365@gmail.com`

### 7.3 자동화 정책

Chrome 로그인은 자동화하지 않는다.

이유:

* 비밀번호 자동 입력은 보안상 위험하다.
* 2단계 인증이 개입될 수 있다.
* Google 로그인 자동화는 계정 보안 정책에 의해 차단될 수 있다.
* 브라우저 프로필 자동 조작은 안정성이 낮다.

### 7.4 구현 방식

ResetFlow는 다음까지만 처리한다.

* Chrome 설치
* Chrome 실행
* 로그인할 계정 목록 표시
* 기본 계정 강조 표시
* 수동 완료 체크박스 제공

### 7.5 UI 표시 예시

[ ] Chrome 설치
[ ] Chrome 실행

## 9. 전원 및 성능 설정

### 9.1 전원 고성능

#### 목적

데스크톱 환경에서 전원 옵션을 고성능으로 설정한다.

#### 대상

* 데스크톱 PC
* 노트북 제외

#### 사용자가 적은 조건

```text
전원 고성능 (노트북X)
```

#### 자동화 가능 여부

가능.

#### 조건 처리

ResetFlow는 실행 중인 장치가 노트북인지 확인한다.

노트북으로 판단되면 해당 기능을 자동 비활성화하거나 경고를 표시한다.

#### UI 표시 예시

```text
[ ] 전원 옵션 고성능 설정
    조건: 데스크톱에서만 권장
    노트북에서는 기본 Off 유지
```

---

### 9.2 NVIDIA 고성능 및 저지연 설정

#### 목적

NVIDIA GPU 환경에서 성능 중심 설정을 적용한다.

#### 대상

* NVIDIA GPU가 있는 데스크톱
* 노트북 제외

#### 사용자가 적은 조건

```text
NVIDIA 고성능, 저지연 (노트북X)
```

#### 자동화 가능 여부

부분 자동화.

NVIDIA 제어판 설정은 시스템 구성과 드라이버 버전에 따라 자동화 안정성이 낮다.

#### 처리 방식

초기 버전에서는 다음 방식으로 처리한다.

* NVIDIA GPU 존재 여부 확인
* NVIDIA 제어판 실행
* 설정 체크리스트 표시
* 사용자가 직접 적용 후 완료 체크

#### 체크리스트 예시

```text
[ ] NVIDIA 제어판 열기
[ ] 전원 관리 모드: 최고 성능 선호
[ ] 저지연 모드: 켜기 또는 울트라
[ ] 수직 동기화 설정 확인
```

## 10. 소리 설정

### 10.1 Windows 소리 구성

#### 목적

Windows 시스템 효과음을 끄고 통신 시 자동 볼륨 조절을 방지한다.

#### 사용자가 적은 기존 흐름

```text
소리 → 소리 - 소리 없음
통신 - 아무 작업 안 함
```

#### 자동화 대상

* 사운드 구성표: 소리 없음
* 통신 탭: 아무 작업 안 함

#### 자동화 가능 여부

부분 자동화.

레지스트리 기반 변경은 가능할 수 있으나 Windows 버전별 검증이 필요하다.

## 15. 드라이버 설치

### 15.1 3DP

#### 목적

포맷 후 누락된 드라이버를 확인하고 설치한다.

#### 사용자가 적은 항목

```text
3DP
드라이버 설치
```

#### 자동화 가능 여부

반자동.

드라이버 설치는 시스템 안정성에 영향을 줄 수 있으므로 완전 자동화하지 않는다.

#### 처리 방식

* 3DP 설치 또는 실행
* 드라이버 설치 안내 표시
* 사용자가 직접 설치
* 완료 체크박스 제공

### 15.2 드라이버 자동화 정책

드라이버 설치는 ResetFlow의 자동 롤백 대상에서 제외한다.

이유:

* 잘못된 드라이버 설치 시 시스템 문제가 커질 수 있음
* 설치 후 재부팅이 필요한 경우가 많음
* 제조사/장치/OS 버전에 따라 설치 방식이 다름
* 자동 제거가 안전하지 않음

* 생성 결과를 로그에 기록한다.

# TO DO

## 30. 인코딩 및 저장소 정책

### 30.1 파일 인코딩

모든 소스 파일과 문서 파일은 UTF-8로 저장한다.

### 30.2 `.editorconfig`

```ini
root = true

[*]
charset = utf-8
end_of_line = crlf
insert_final_newline = true
trim_trailing_whitespace = true

[*.md]
trim_trailing_whitespace = false
```

### 30.3 `.vscode/settings.json`

```json
{
  "files.encoding": "utf8",
  "files.autoGuessEncoding": false,
  "files.eol": "\r\n"
}
```

### 30.4 `.gitattributes`

```gitattributes
* text=auto

*.cs text eol=crlf
*.xaml text eol=crlf
*.json text eol=crlf
*.md text eol=crlf
*.ps1 text eol=crlf
```

### 30.5 Codex 작업 지시

Codex 또는 AI 코딩 도구에 작업을 맡길 때 다음 조건을 명시한다.

```text
모든 소스 파일은 UTF-8로 저장한다.
한글 주석이 깨지지 않도록 CP949, EUC-KR, ANSI 인코딩을 사용하지 않는다.
.editorconfig와 .vscode/settings.json 기준을 따른다.
기존 파일이 UTF-8이 아니면 UTF-8로 변환한 뒤 수정한다.
```

## 32. 성공 기준

ResetFlow의 성공 기준은 다음과 같다.

* 포맷 직후 Windows에서 실행 가능해야 한다.
* 모든 기능은 기본 Off 상태여야 한다.
* 사용자가 선택한 기능만 실행되어야 한다.
* 실행 전 상태를 백업해야 한다.
* 실패 시 가능한 범위에서 롤백해야 한다.
* 실패 원인을 확인할 수 있는 로그를 남겨야 한다.
* 자동화 불가능한 항목은 체크리스트로 명확히 분리해야 한다.
* Windows Sandbox 또는 VM에서 반복 테스트 가능해야 한다.
* 최소한 다음 기능은 안정적으로 동작해야 한다.

  * 마우스 가속도 끄기
  * 파일 탐색기 설정
  * 다크 모드 설정
  * 문서 폴더 구조 생성
  * 사진 폴더 구조 생성
  * 기본 프로그램 설치
  * 로그 생성
  * 오류 처리

## 33. 최종 정리

ResetFlow는 Windows 포맷 후 개인 환경을 빠르게 복구하기 위한 자동화 도구이다.

핵심은 모든 작업을 무리하게 자동화하는 것이 아니다.

자동화 가능한 작업은 프로그램이 처리하고, 계정 로그인, 드라이버 설치, NVIDIA 설정, 시작 화면, 작업 표시줄처럼 불안정하거나 보안상 위험한 작업은 체크리스트로 분리한다.

초기 버전에서는 다음 구조를 먼저 완성한다.

1. 기능 On/Off 시스템
2. 실행 전 백업
3. 설정 적용
4. 검증
5. 실패 시 롤백
6. 로그 생성
7. 수동 체크리스트

그 후 프로그램 설치, 세부 Windows 설정, 개발 환경 복구 기능을 단계적으로 확장한다.
