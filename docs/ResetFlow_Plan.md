# ResetFlow 프로그램 기획서

## 1. 프로그램 개요

**ResetFlow**는 Windows 포맷 또는 초기화 직후 사용자가 반복적으로 설정하는 개인 환경을 자동으로 복구하는 Windows 자동화 프로그램이다.

사용자는 USB, 외장 드라이브, 클라우드 저장소 등을 통해 `ResetFlow.exe`를 새 Windows 환경으로 옮긴 뒤 실행한다. 프로그램은 GUI 창을 제공하며, 사용자는 원하는 설정 항목을 개별적으로 On/Off 할 수 있다. 모든 항목은 기본값 Off 상태로 제공된다.

사용자가 필요한 항목을 선택하고 Start 버튼을 누르면 ResetFlow는 선택된 설정을 순서대로 적용한다. 실행 중 오류가 발생하면 실행 전 상태로 복구하고, 사용자에게 실패한 기능, 오류 원인, 디버그 로그 위치를 제공한다.

---

## 2. 개발 목적

Windows 포맷 이후 반복적으로 수행하는 초기 설정 작업을 자동화하여 다음 문제를 줄인다.

* 매번 같은 설정을 수동으로 반복하는 시간 낭비
* 설정 누락
* 잘못된 설정 적용
* 개발 환경 복구 과정의 불안정성
* 포맷 후 프로그램 설치 및 환경 세팅의 비일관성

ResetFlow의 목표는 단순한 설치 프로그램이 아니라, 사용자가 원하는 개인 Windows 환경을 빠르고 안전하게 재구성하는 자동화 도구를 만드는 것이다.

## 3. 핵심 컨셉

### 3.1 기본 상태는 Off

모든 기능은 기본적으로 Off 상태이다.
사용자가 명시적으로 On 한 기능만 실행한다.

### 3.2 전체 On / 전체 Off 제공

사용자는 개별 선택 외에도 다음 버튼을 사용할 수 있다.

* 전체 On
* 전체 Off

### 3.3 Start 버튼 기반 실행

사용자가 기능을 선택한 뒤 Start 버튼을 누르면 선택된 기능만 실행된다.

### 3.4 실행 전 상태 백업

각 기능은 실행 전에 현재 상태를 백업한다.

예시:

* 레지스트리 값 백업
* 설정 파일 백업
* 기존 프로그램 설치 여부 확인
* 기존 환경 변수 백업
* 기존 폴더 또는 파일 백업

### 3.5 실패 시 롤백

실행 도중 오류가 발생하면 ResetFlow는 실행 전 상태로 복구한다.

기본 정책은 **All-or-Nothing 방식**이다.

즉, 선택된 기능 중 하나라도 실패하면 이전에 성공한 기능까지 가능한 범위에서 모두 되돌린다.

### 3.6 로그 제공

오류 발생 시 사용자는 다음 정보를 확인할 수 있다.

* 실패한 기능 이름
* 실패 단계
* 사용자용 오류 메시지
* 디버그 로그 파일 경로
* 내부 예외 메시지
* 실행된 명령어
* 표준 출력
* 표준 오류
* 롤백 성공 여부

## 4. 주요 사용자 시나리오

### 4.1 기본 실행 흐름

1. 사용자가 포맷된 Windows에서 `ResetFlow.exe`를 실행한다.
2. 프로그램 창이 열린다.
3. 모든 기능은 Off 상태로 표시된다.
4. 사용자가 필요한 기능만 On 한다.
5. 사용자가 Start 버튼을 누른다.
6. 프로그램이 관리자 권한 필요 여부를 확인한다.
7. 선택된 기능의 실행 전 상태를 백업한다.
8. 선택된 기능을 순서대로 적용한다.
9. 각 기능 적용 후 검증을 수행한다.
10. 모든 기능이 성공하면 완료 화면을 보여준다.
11. 실패한 경우 자동 롤백 후 오류 요약과 로그를 보여준다.

## 5. 예시 기능: 마우스 가속도 끄기

### 기능명

마우스 가속도 비활성화

### 목적

Windows의 마우스 포인터 가속 설정을 비활성화하여 일정한 마우스 입력 환경을 만든다.

### 기본값

Off

### 실행 방식

Windows 사용자 레지스트리의 마우스 관련 값을 수정한다.

### 실행 전 백업

현재 마우스 관련 레지스트리 값을 백업 파일로 저장한다.

### 적용

마우스 가속도와 관련된 레지스트리 값을 비활성화 값으로 변경한다.

### 검증

변경 후 레지스트리 값을 다시 읽어 의도한 값으로 적용되었는지 확인한다.

### 롤백

백업해 둔 레지스트리 값을 다시 복원한다.

### 주의사항

일부 설정은 즉시 반영되지 않을 수 있으며, 로그아웃 또는 재부팅 후 완전히 적용될 수 있다.

## 9. 오류 처리 정책

### 9.1 오류 발생 시 기본 동작

기능 실행 중 오류가 발생하면 즉시 남은 기능 실행을 중단한다.

그 후 다음 순서로 처리한다.

1. 실패한 기능 기록
2. 오류 내용 기록
3. 이미 적용된 기능을 역순으로 롤백
4. 롤백 결과 기록
5. 사용자에게 오류 요약 표시
6. 디버그 로그 파일 위치 제공

### 9.2 사용자에게 보여줄 오류 정보

사용자에게는 기술적인 예외 전체를 바로 보여주지 않고, 이해 가능한 요약을 먼저 보여준다.

예시:

```text
마우스 가속도 비활성화에 실패했습니다.
레지스트리 값을 수정하는 중 권한 문제가 발생했습니다.
실행 전 상태로 복구를 시도했으며, 복구에 성공했습니다.

자세한 로그:
logs/2026-06-01_14-30-22.log
```

### 9.3 디버그 로그에 기록할 정보

디버그 로그에는 다음 정보를 기록한다.

* 실행 시간
* ResetFlow 버전
* Windows 버전
* 관리자 권한 여부
* 선택된 기능 목록
* 기능별 실행 시작 시간
* 기능별 실행 종료 시간
* 실행 명령어
* 표준 출력
* 표준 오류
* 예외 메시지
* 스택 트레이스
* 백업 파일 경로
* 롤백 결과

## 10. 롤백 정책

모든 기능이 완벽히 롤백 가능한 것은 아니다.
따라서 기능마다 롤백 가능 여부를 명확히 분리한다.

### 10.1 완전 롤백 가능 기능

* 레지스트리 값 변경
* 설정 파일 변경
* 환경 변수 변경
* 폴더 생성
* 단순 파일 복사

### 10.2 부분 롤백 기능

* 프로그램 설치
* 드라이버 설치
* Windows 기능 활성화
* 네트워크 설정 변경

### 10.3 롤백 불가 또는 위험 기능

* 대형 프로그램 설치 후 자동 제거
* 시스템 업데이트
* 드라이버 업데이트
* 보안 정책 변경

롤백이 불완전한 기능은 UI에서 별도 경고를 표시한다.

예시:

```text
이 기능은 실패 시 완전한 복구가 불가능할 수 있습니다.
계속 진행하시겠습니까?
```

## 13. 기술 스택 제안

### 13.1 추천 구조

* 언어: C#
* GUI: WPF 또는 WinUI
* 실행 방식: 단일 Windows EXE
* 설정 저장: JSON
* 로그 저장: 텍스트 로그 또는 JSON 로그

* Windows 전용 프로그램 제작에 적합하다.
* 레지스트리, 프로세스 실행, 파일 시스템 접근이 쉽다.
* GUI 앱 제작이 비교적 안정적이다.
* EXE 배포가 쉽다.
* 향후 모듈 구조로 확장하기 좋다.

## 14. 테스트 전략

### 14.1 단위 테스트

다음 로직은 일반 단위 테스트로 검증한다.

* 설정 파일 파싱
* 기능 선택 로직
* 로그 생성 로직
* 실행 순서 정렬
* 롤백 순서 정렬
* 오류 처리 로직

### 14.2 Docker 테스트

Docker는 제한적으로 사용한다.

Docker에서 테스트할 수 있는 영역:

* 설정 파일 파싱
* 로그 포맷 검증
* 명령 실행 래퍼 테스트
* 비즈니스 로직 테스트
* 일부 CLI 로직 테스트

Docker에서 테스트하기 어려운 영역:

* 실제 Windows GUI 설정 변경
* 사용자 레지스트리 변경
* Windows Shell 설정
* 관리자 권한 흐름
* 재부팅 후 설정 유지 여부
* 포맷 직후 Windows 환경 재현

### 14.3 Windows Sandbox 테스트

Windows Sandbox는 초기화된 Windows 환경에서 실행 테스트를 하기 좋다.

테스트 항목:

* ResetFlow.exe 실행 여부
* 관리자 권한 요청 여부
* 마우스 가속도 설정 변경 여부
* 레지스트리 변경 여부
* 로그 파일 생성 여부
* 실패 시 롤백 여부
* 프로그램 종료 후 재실행 안정성

### 14.4 VM 스냅샷 테스트

Hyper-V, VMware, VirtualBox 같은 VM을 사용하면 더 정밀한 테스트가 가능하다.

테스트 방식:

1. 깨끗한 Windows VM 생성
2. 스냅샷 저장
3. ResetFlow 실행
4. 결과 확인
5. 스냅샷으로 복원
6. 다른 기능 조합 테스트

VM 스냅샷 테스트는 실제 배포 전 최종 검증에 적합하다.

## 18. 성공 기준

ResetFlow의 성공 기준은 다음과 같다.

* 포맷 직후 Windows에서 실행 가능해야 한다.
* 모든 기능은 기본 Off 상태여야 한다.
* 사용자가 선택한 기능만 실행되어야 한다.
* 실행 전 상태를 백업해야 한다.
* 실패 시 가능한 범위에서 실행 전 상태로 복구해야 한다.
* 실패 원인을 추적할 수 있는 로그를 남겨야 한다.
* 최소 1개 이상의 실제 Windows 설정 자동화 기능이 안정적으로 동작해야 한다.
* Windows Sandbox 또는 VM에서 반복 테스트가 가능해야 한다.

## 19. 결론

ResetFlow는 Windows 초기 설정을 자동화하는 개인 환경 복구 도구이다.

핵심은 많은 기능을 넣는 것이 아니라, 안전하게 실행하고 실패 시 복구할 수 있는 구조를 먼저 만드는 것이다. 초기 버전에서는 마우스 가속도 끄기처럼 범위가 작고 검증 가능한 기능부터 구현한다.

이후 앱 설치, 개발 환경 복원, 설정 파일 복원 기능을 단계적으로 확장한다.
